# RAG 流程設計

## 目前階段

第四階段採用本機 Hybrid RAG 檢索，不依賴外部 API：

- 關鍵字檢索：判斷課程、報名、補助、甄試、聯絡、職前、在職等明確詞彙。
- TF-IDF 向量檢索：將知識庫 chunk 與使用者問題轉為本機向量，使用 cosine similarity 排序。
- Metadata 過濾：依 114/115 期別、職前/在職主題進行過濾，避免混用資料。

此版本可作為正式 Embedding 與向量資料庫上線前的展示版。

## 匯入流程

1. 讀取 `AI智慧應用產業人才培訓班_整合知識庫.txt`
2. 清理文字
3. 依標題、分隔線與主題切割 chunk
4. 加入 metadata
5. 建立關鍵字索引
6. 建立 TF-IDF 向量索引

## 查詢流程

1. 使用者輸入問題
2. 系統判斷問題類型
3. 推論查詢過濾條件，例如 114、115、職前、在職
4. 先用 metadata 過濾不適用的 chunk
5. 計算關鍵字分數
6. 計算 TF-IDF cosine similarity
7. 合併分數並排序
8. 取回前幾筆 chunk
9. 產生客服格式回答
10. 顯示來源依據與注意事項
11. 寫入問答紀錄
12. 收集使用者回饋

## Chunk Metadata

- 文件名稱
- chunk 編號
- 主題分類
- 年度
- 期別
- 是否需官方確認

## 防幻覺規則

- 檢索不到內容時，回答「目前知識庫沒有明確資料」
- 補助、津貼、學習獎勵金與錄取結果不可保證
- 最新梯次與報名狀態需以官方平台為準
- 不得混用 114 年第 01 期與 115 年第 02 期
- 不得混用職前訓練與在職訓練

## 後續正式向量化規劃

正式版可將目前 `TfidfIndex` 替換為：

- OpenAI Embedding
- Supabase pgvector
- Pinecone
- Weaviate

後端 API 與前端不需要大幅改動，只需替換 retriever 實作。
